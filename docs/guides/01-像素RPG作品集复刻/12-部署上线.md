```
├── assets/
│   ├── js/
│   │   ├── game.js         ← Phaser 游戏主逻辑
│   │   ├── player.js       ← 玩家类
│   │   ├── npc.js          ← NPC 系统
│   │   ├── modal-manager.js ← 模态管理器

│   ├── css/
│   │   └── style.css       ← 样式表
│   ├── maps/
│   │   └── world.json      ← Tiled 导出的地图 JSON
│   └── tilesets/
│       └── tileset.png     ← 瓦片集图片
├── phaser.min.js           ← Phaser 库（或通过 CDN 引入）
└── ...（可选：favicon、robots.txt 等）
```

> **关键：** `index.html` 必须在根目录。`assets/` 内的路径必须与 HTML 中引用的路径一致。

### 1.2 HTML 检查

在 `index.html` 中确认：

```html
<!-- ✅ 路径使用相对路径（不以 / 开头） -->
<script src="assets/js/game.js"></script>

<!-- ❌ 避免使用绝对路径（除非确认服务器配置） -->
<!-- <script src="/assets/js/game.js"></script> -->

<!-- ✅ charset 声明 -->
<meta charset="UTF-8">

<!-- ✅ viewport（移动端适配） -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

### 1.3 JavaScript 检查

```javascript
// ✅ 所有文件路径使用相对路径
this.load.image('tiles', 'assets/tilesets/tileset.png');
this.load.tilemapTiledJSON('world', 'assets/maps/world.json');

// ❌ 避免使用 assets/ 前缀以外的路径
// this.load.image('tiles', '/assets/tilesets/tileset.png');

// ✅ Phaser 配置中的渲染模式
const config = {
  type: Phaser.AUTO,  // 自动选择 WebGL 或 Canvas
  width: 800,
  height: 600,
  // ...
  scale: {
    mode: Phaser.Scale.FIT,       // 自适应缩放
    autoCenter: Phaser.Scale.CENTER_BOTH,
  },
};
```

### 1.4 CSS 检查

```css
/* ✅ 确保 body 和 html 没有多余的 margin/padding */
html, body {
  margin: 0;
  padding: 0;
  overflow: hidden;  /* 防止出现滚动条 */

/* ✅ 游戏容器 */

  height: 100vh;
```

## 2. 部署到 Netlify（推荐）

Netlify 是最简单的部署方式，免费额度足够个人作品集使用。

### 2.1 准备工作

确保项目根目录有以下可选文件：

**`netlify.toml`（推荐，放在根目录）：**

```toml
[build]
  publish = "."

[[redirects]]
  from = "/sk/*"
  to = "/index.html"
  status = 200

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

或者使用更简单的 **`_redirects`** 文件（无扩展名，放在根目录）：

```
/sk/*  /index.html  200
/*     /index.html  200
```

### 2.2 部署方式一：拖拽部署（最简单）

1. 打开 [app.netlify.com](https://app.netlify.com)
2. 登录（推荐用 GitHub 账号）
3. 将整个**项目文件夹**拖拽到 Netlify 的部署区域
4. 等待上传和构建完成（约 10-30 秒）
5. Netlify 会生成一个随机域名（如 `random-name-123456.netlify.app`）
6. 点击 "Site settings" → "Change site name" 改为自己喜欢的名字

### 2.3 部署方式二：Git 自动部署（推荐用于团队协作）

1. 将项目推送到 GitHub 仓库：

```bash
cd /你的项目路径
git init
git add .
git commit -m "Initial commit: pixel RPG portfolio"
git remote add origin https://github.com/你的用户名/仓库名.git
git branch -M main
git push -u origin main
```

2. 在 Netlify 中选择 "Import an existing project"
3. 连接 GitHub，选择你的仓库
4. Build settings（本项目不需要构建步骤）：
   - Build command：留空
   - Publish directory：留空（或填 `.`）
5. 点击 "Deploy site"

### 2.4 自定义域名（可选）

1. 在 Netlify 项目页面 → "Domain settings"
2. 点击 "Add custom domain"
3. 输入你的域名（如 `peteroravec.sk`）
4. 按照提示在域名服务商处添加 DNS 记录（CNAME 指向 `your-site.netlify.app`）

## 3. 部署到 Vercel

Vercel 是另一个优秀的部署平台，类似 Netlify。

### 3.1 部署方式一：拖拽部署

1. 打开 [vercel.com](https://vercel.com)
2. 登录（推荐用 GitHub 账号）
3. 点击 "New Project"
4. 将项目文件夹拖拽到上传区域
5. Vercel 自动检测为静态站点，直接部署
6. 生成 `your-project.vercel.app` 域名

### 3.2 部署方式二：CLI 部署

```bash
# 安装 Vercel CLI
npm install -g vercel

# 在项目根目录执行
vercel

# 按照提示完成配置
# > Set up and deploy? Y
# > Which scope? 选择你的账号
# > Link to existing project? N
# > What's your project's name? pixel-rpg-portfolio
# > In which directory is your code? ./
# > Want to override settings? N
```

### 3.3 Vercel 配置文件

**`vercel.json`（放在根目录）：**

```json
{
  "rewrites": [
    { "source": "/sk/:path*", "destination": "/index.html" },
    { "source": "/:path*", "destination": "/index.html" }
  ]
}
```

## 4. 部署到 GitHub Pages（完全免费）

GitHub Pages 是免费的静态站点托管，适合开源项目。

### 4.1 准备工作

创建 `index.html` 的同级文件 **`.nojekyll`**（无扩展名，内容为空）：

```bash
# 在项目根目录创建 .nojekyll 文件
touch .nojekyll
```

> 这个文件告诉 GitHub Pages 不要用 Jekyll 处理你的站点（否则以 `_` 开头的文件会被忽略）。

### 4.2 部署步骤

**方法一：从主分支根目录部署**

1. 将项目推送到 GitHub：

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git branch -M main
git push -u origin main
```

2. 在 GitHub 仓库页面 → Settings → Pages
3. Source：选择 "Deploy from a branch"
4. Branch：选择 `main`，文件夹选择 `/ (root)`
5. 点击 Save
6. 等待 1-2 分钟，访问 `https://你的用户名.github.io`

**方法二：从 `gh-pages` 分支部署**

1. 安装 `gh-pages`：

```bash
npm install -g gh-pages
```

2. 发布到 gh-pages 分支：

```bash
gh-pages -d .
```

3. 在 GitHub 仓库 → Settings → Pages → Branch 选择 `gh-pages`

**方法三：手动创建 gh-pages 分支**

```bash
git checkout -b gh-pages
git push origin gh-pages
# 切回 main
git checkout main
```

### 4.3 GitHub Pages 的 base 路径问题

如果你的仓库名不是 `你的用户名.github.io`，而是类似 `你的用户名.github.io/portfolio`，则需要在路径前加仓库名。

解决方式：在 HTML 中使用相对路径（不用 `/` 开头），GitHub Pages 会自动处理。

```html
<!-- ✅ 相对路径 — 任何部署环境都适用 -->
<script src="assets/js/game.js"></script>
<link rel="stylesheet" href="assets/css/style.css">

<!-- ❌ 绝对路径 — 可能导致资源 404 -->
<!-- <link rel="stylesheet" href="/assets/css/style.css"> -->
```

## 5. 跨域资源 (CORS) 问题

如果你通过 CDN 引入了 Phaser 或其他资源，一般不会有 CORS 问题。但如果你在 JS 中加载了外部资源，可能需要处理。

```html
<!-- ✅ 使用 CDN 引入 Phaser（推荐） -->
<script src="https://cdn.jsdelivr.net/npm/phaser@3.60.0/dist/phaser.min.js"></script>

<!-- Phaser 会自动处理 CORS -->
```

对于你项目中的 Tiled 地图 JSON 和 tileset 图片，因为它们与 `index.html` 同源，不会遇到 CORS 问题。

## 7. 常见部署问题

| 问题 | 现象 | 解决方法 |
|------|------|----------|
| **资源 404** | 控制台中 JS/CSS 文件加载失败 | 检查 HTML 中引用路径为相对路径（`assets/js/game.js`），不要以 `/` 开头 |
| **页面空白** | 没有报错但一直是白屏 | 检查 Phaser 是否正确加载；检查 game.js 中的 `Phaser.Scale.FIT` 配置；打开 F12 查看 Network 标签 |
| **地图不显示** | 游戏加载了但地图是黑的 | 检查 `world.json` 路径是否正确；确认 tileset 图片路径与 JSON 中 `"image"` 字段一致 |
| **Tiled JSON 报错** | `Uncaught TypeError: tileset is null` | JSON 中 tileset 的 `"image"` 字段应为相对路径，如 `"image": "../tilesets/tileset.png"` |
| **`/sk/` 路径 404** | 访问 `/sk/` 时返回 "Page Not Found" | 确认有 `_redirects`（Netlify）或 `vercel.json`（Vercel）；GitHub Pages 使用 404.html 作为 Fallback |
| **GitHub Pages 文件不更新** | 修改代码后页面没变化 | 清除浏览器缓存（Ctrl+F5）；确认 push 到了正确的分支；设置中确认 Pages 源分支正确 |
| **移动端无法操作** | 手机上玩家无法移动 | 检查虚拟摇杆是否正确初始化；检查 CSS `touch-action: none` |
| **斯洛伐克语乱码** | 特殊字符显示为问号或方块 | 确保所有文件保存为 UTF-8 编码；HTML 中有 `<meta charset="UTF-8">` |
| **部署后路径不对** | 某些功能在本地正常，部署后失效 | Netlify/Vercel 部署环境与本地一致（无子路径）；GitHub Pages 如果有项目名子路径，需用相对路径 |
| **域名不生效** | 自定义域名访问不了 | 等待 DNS 传播（最长 48 小时，通常 5-30 分钟）；检查 CNAME 记录是否正确指向 |

## 8. GitHub Pages 的 404 回退方案

GitHub Pages 默认不支持 SPA 路由（如 `/sk/`）。解决方式是创建 `404.html`：

```html
<!-- 404.html — 放在根目录 -->
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <script>
    // 将路径参数传递给 index.html
    sessionStorage.redirect = location.pathname + location.search;
    location.replace('/');
  </script>
</head>
<body></body>
</html>
```

并在 `index.html` 的 `<head>` 中恢复路径：

```html
<script>
  (function() {
    var redirect = sessionStorage.redirect;
    delete sessionStorage.redirect;
    if (redirect && redirect !== location.pathname) {
      history.replaceState(null, null, redirect);
    }
  })();
</script>
```

## 章节小结

- **Netlify** 是最推荐的部署方案（拖拽即用、免费、内置 SPA 路由支持）
- **Vercel** 是很好的备选（类似 Netlify，CLI 工具强大）
- **GitHub Pages** 是完全免费的方案，但需要额外处理 SPA 路由（404.html 技巧）
- **部署前必须检查**：相对路径、文件编码、SPA 路由配置
- **所有路径使用相对路径**（`assets/js/game.js` 而非 `/assets/js/game.js`），确保在任何部署环境都能正常工作
