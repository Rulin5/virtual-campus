# 产品需求文档（PRD）

## 虚拟校园平台 — 基于 PeterOravec.com 的 1:1 复刻与平台化改造

---

## 一、项目愿景

### 1.1 最终目标

构建一个**可复刻、可配置的"虚拟校园"平台**，将真实校园的建筑、机构、人员、事件映射到像素 RPG 风格的虚拟世界中。用户通过操控角色在校园地图上走动、进入建筑、与 NPC 对话、完成任务，实现虚拟与现实的深度互动。

平台的核心价值：**用户只需配置，即可生成专属虚拟场景**——不仅限于校园，未来可扩展至博物馆、商场、企业园区等实体空间。

### 1.2 参考样本

对标 [peteroravec.com](https://peteroravec.com) —— 一个将个人作品集做成复古 RPG 游戏的网站：
- 像素风格瓦片地图 + Phaser 3 游戏引擎
- 角色移动、NPC 系统、相机跟随
- 走进建筑弹出模态窗口，展示内容
- NES.css 复古 UI、"Press Start 2P" 像素字体
- 移动端虚拟摇杆、响应式适配

该网站证明了"RPG 游戏 + 信息展示"模式的可行性和魅力。我们 Phase 1 的目标就是 1:1 复刻它，掌握全部技术细节，然后以此为引擎，改造为虚拟校园平台。

### 1.3 产品价值

| 维度 | 说明 |
|------|------|
| 正能量宣传 | 承载校园新闻、考试通知、活动公告 |
| 实用功能 | 链接图书馆系统、选课系统、一卡通等 |
| 趣味互动 | 外卖剧情、相亲角、校园寻宝等社交玩法 |
| 商业价值 | 成功后可作为解决方案向博物馆、商场等 B 端客户输出 |
| 团队积累 | GitHub 高 Star 数、扎实的项目经历，助力保研或大厂 offer |

### 1.4 开发原则

- **文档先行**：编码前必须产出详细规划文档，两位成员分别独立产出形成对照组，比对融合后确定最优方案
- **螺旋迭代**：遵循软件工程螺旋法则，从小功能开始，逐步扩大
- **三大模块**：前端游戏平台（最难）、后端 API、后台管理系统
- **前沿技术**：鼓励采用高含金量技术栈（WASM、Rust/Go 后端、容器化、CI/CD）

## 二、Phase 1 — 对标样本 1:1 复刻

> **目标**：完整复刻 peteroravec.com，掌握 Phaser 3 游戏引擎 + 瓦片地图 + NPC 系统 + 模态交互的全部技术细节，为平台化改造打下基础。

### 2.1 复刻范围

对原站进行**像素级 1:1 还原**：

- 每一块 UI（预加载 GIF → Play 按钮 → 游戏画布 → 10 个模态窗口）全部照搬
- 每一种交互（键盘走路、手机摇杆、走进建筑弹窗、Big Map VHS 特效、卡片全息光效）全部照搬
- 每一个像素细节（NES.css 按钮、"Press Start 2P"字体、pixel-corners 边框、自定义十字光标）全部照搬
- 地图数据直接使用原站的 `final_map.json`（140×140 瓦片、24 层）
- 所有文案内容、图片资源全部使用原站资源

### 2.2 复刻版与原版的技术差异

| 维度 | 原版 | 复刻版 | 理由 |
|------|------|--------|------|
| 应用框架 | Angular 19 | 原生 JavaScript (ES Module) | 减少构建依赖，纯静态部署 |
| 游戏引擎 | Phaser.js 3 | Phaser.js 3 | 保持一致 |
| UI 框架 | NES.css | NES.css | 保持一致 |
| 字体 | "Press Start 2P" | "Press Start 2P" | 保持一致 |
| 部署 | Netlify | 任意静态托管 | 灵活性 |

Angular 在原站中只负责"承载 Phaser 画布 + 渲染模态窗口 DOM"，用原生 JS 完全可以做到一模一样的视觉效果和交互。

### 2.3 全局特性

| 功能 | 描述 |
|------|------|
| 自定义光标 | 像素风格十字准星光标（全局生效） |
| 像素字体 | "Press Start 2P" Google Font |
| NES.css UI 组件 | 按钮、列表、图标均使用 NES.css 风格 |
| 像素边框装饰 | `.pixel-corners` 类名实现像素风格窗口边框 |
| 滚动条样式 | 细滚动条，半透明黑色，圆角 |
| 多语言支持 | 英语 / 斯洛伐克语（通过 URL 路径切换） |
| SEO | Open Graph、Twitter Card、JSON-LD 结构化数据 |

### 2.4 加载阶段

```
打开网站 → "Loading..." 覆盖层 → 预加载 GIF + 进度条 + 百分比 → Play 按钮界面
```

| 元素 | 说明 |
|------|------|
| Loading 覆盖层 | 纯白背景，居中文字 |
| 进度条 | CSS 动画，配合百分比数字 |
| 预加载动画 | 310×310 像素风格 GIF |
| Play 界面 | Logo（441×282）+ 红色 NES 风格 "Play" 按钮 |
| 快捷入口 | "No time to explore?" + LinkedIn 链接按钮 |

### 2.5 游戏阶段

#### 2.5.1 游戏画布
- Phaser 3 渲染，WebGL 优先，自动降级到 Canvas 2D
- 渲染分辨率：480×270，CSS `image-rendering: pixelated` 拉伸至全屏
- 画布固定定位，覆盖整个视口

#### 2.5.2 玩家角色
- 键盘方向键 + WASD 控制移动
- 移动端虚拟摇杆（触摸控制）
- 8 方向移动 + 碰撞检测

#### 2.5.3 相机与地图
- 平滑跟随玩家
- **分块加载**：地图切割为小块，仅加载玩家周围区域，超出范围则销毁（核心优化，后续平台化的关键技术）

#### 2.5.4 NPC 系统

| NPC 类型 | 行为 |
|----------|------|
| 行人 | 沿预定义路径行走 |
| 汽车 | 4 个独立轮子、刹车灯发光、转向灯自动激活 |
| 鬼魂 | 漂浮移动 |
| 舞者 | 特殊动画 |
| 怪物 | 巡逻移动 |
| 人群 | Crowd Manager 控制，按地图区域出现/消失 |

- 视锥裁剪：超出相机范围则销毁精灵，回到视野则重建
- 寻路使用 EasyStar.js，在 Web Worker 中运行，不阻塞主线程

#### 2.5.5 交互点
地图上分布标记点，玩家走到附近触发交互（弹出模态窗口）：
- **信息点**：Technologies、About Me、CV、Projects、Contact、Under the Hood
- **Memo 点**：6 张可收集卡片的隐藏位置

#### 2.5.6 触摸提示
浮动手指图标，CSS 动画往复移动，提示用户可点击交互。

### 2.6 模态窗口（原站共 10 个）

#### 2.6.1 通用结构
```
[关闭按钮 ×] [像素边框窗口] [内容区域] [返回顶部 ↑]
```

#### 2.6.2 Technologies（技术栈）
4 个核心技术卡片（Angular / Node.js / Express.js / JavaScript）+ "Other technologies" 列表

#### 2.6.3 About Me（关于我）
头像照片 + 姓名 + 职位 + LinkedIn 链接 + 3 段自我介绍

#### 2.6.4 CV（简历时间线）
5 家公司时间线（GAMO → SCR → Kremsa Digital → Bethereum → VUB Bank），每家含项目列表（可展开/折叠）

#### 2.6.5 Projects（项目）
3 个个人项目：eUTxO.org / Angular.sk / 旧版作品集

#### 2.6.6 Contact（联系方式）
LinkedIn + Email

#### 2.6.7 Memo Cards × 6
每张卡片含全息特效 / 反光蚀刻 / 闪光 / 棱镜等视觉效果，支持 ← → 导航

#### 2.6.8 Big Map（全局地图）
CRT/VHS 老电视效果（RGB 分离、扫描线、追踪线），含图例和玩家位置脉冲动画

#### 2.6.9 Under the Hood（技术内幕）
6 个标签页：Architecture / Phaser.js / Chunk System / NPC System / Tiled Editor / Optimization

### 2.7 移动端适配

| 功能 | 说明 |
|------|------|
| 虚拟摇杆 | 触摸拖动控制移动 |
| 响应式 UI | 模态窗口自适应屏幕尺寸 |
| 横屏提示 | 竖屏时显示"旋转设备"图标 + 文字 |
| 动态视口 | `100dvh` 处理 iOS Safari 地址栏问题 |
| 渲染降级 | 弱设备自动切换到 Canvas 2D |

## 三、Phase 2 — 虚拟校园平台改造

> **目标**：将 Phase 1 的技术引擎从"个人作品集"改造为"可配置的虚拟校园平台"，加入后端服务、数据库、后台管理，实现完整的闭环体验。

### 3.1 平台架构概览

```
用户浏览器
├── 平台界面：React + TypeScript（登录、校园选择、排行榜）
├── 游戏场景：Phaser 3（角色、地图、NPC、碰撞）
├── 地图系统：Tiled Map Editor → JSON 配置
├── 实时通信：WebSocket（在线角色、聊天、实时活动）
└── 插件运行：iframe / Web Worker / WASM 沙箱

后端服务
├── API 服务：Go + Gin/Fiber
├── 用户与权限：JWT / OAuth
├── 数据库：PostgreSQL
├── 缓存：Redis
├── 文件存储：MinIO / S3
└── 实时服务：WebSocket

后台管理
├── React + TypeScript + Ant Design Pro
├── 校园创建、地图上传、NPC 编辑、对话配置
├── 任务创建、新闻发布、活动管理、用户管理
└── 可视化地图编辑器（拖入 NPC → 设置传送点 → 绑定剧情 → 发布）

开发部署
├── GitHub Organization + Monorepo
├── Docker Compose（Demo 阶段）
├── GitHub Actions（CI/CD）
├── Nginx（反向代理）
└── Kubernetes（平台扩张阶段）
```

### 3.2 功能需求

#### 3.2.1 用户系统
- 注册 / 登录（JWT）
- 创建虚拟角色（名称、外观）
- 角色位置和进度保存
- 在线用户列表（WebSocket 实时同步）

#### 3.2.2 多地图系统
- 校园主地图（室外）
- 建筑内部地图（图书馆、教学楼、食堂等）
- 活动副本（临时活动场景）
- 地图间传送点 + 角色位置恢复
- 地图资源按需加载

#### 3.2.3 NPC 与对话系统

NPC 通过 JSON 配置：

```json
{
  "id": "library_teacher",
  "name": "图书馆老师",
  "mapId": "library",
  "position": { "x": 320, "y": 180 },
  "dialogueId": "library_guide",
  "interactionType": "dialogue"
}
```

对话系统支持：
- 多轮对话 + 选项分支
- 条件判断（达到某等级/持有某道具）
- 奖励发放（道具、经验、解锁）
- 触发页面跳转 / 外部链接
- NPC 状态变化

可选用 Yarn Spinner / Ink 剧情脚本，或自研 JSON 剧情配置。

#### 3.2.4 任务系统

```
任务触发 → 显示目标 → 监听行为 → 判断完成 → 发放奖励 → 解锁后续
```

任务类型：对话任务、收集任务、探索任务、限时活动任务

#### 3.2.5 校园信息聚合
- 校园新闻展示（链接学校 RSS/API）
- 考试 / 活动日历
- 链接图书馆系统、选课系统、一卡通
- 虚拟公告板（后台发布，游戏内展示）

#### 3.2.6 趣味互动
- 外卖剧情小游戏
- 相亲角社交功能
- 校园寻宝活动
- 排行榜（学习时长、任务完成数等）

### 3.3 后台管理系统

后台是平台化的关键——**让非技术人员通过配置生成虚拟校园**。

#### 功能清单

| 模块 | 功能 |
|------|------|
| 校园管理 | 创建校园、上传地图、设置出生点 |
| 建筑管理 | 添加建筑、设置进入条件、绑定内部地图 |
| NPC 管理 | 添加 NPC、编辑对话树、设置行走路径 |
| 任务管理 | 创建任务、设置条件与奖励、发布 |
| 新闻管理 | 发布校园新闻、设置过期时间 |
| 活动管理 | 配置活动副本、限时任务 |
| 用户管理 | 查看用户、权限控制 |
| 数据统计 | 访问数据、在线人数、任务完成率 |

#### 可视化地图编辑器

```
上传地图底图
→ 拖入 NPC 到地图
→ 设置传送点（点击地图选坐标）
→ 绘制碰撞区域
→ 绑定剧情脚本
→ 保存 → 即时预览 → 发布
```

### 3.4 插件系统（长期规划）

分三个阶段：

1. **JSON 配置**：创建 NPC、剧情和任务（无需编码）
2. **JavaScript 插件**：开发小游戏和互动功能（iframe / Web Worker 沙箱）
3. **WASM 插件**：运行高性能扩展模块（Rust/Go 编译到 WASM，全沙箱隔离）

插件运行在沙箱环境中，通过权限清单 + API 白名单确保安全。

### 3.5 多租户架构（长期规划）

```
organization（学校/组织）
  ├── campus A（主校区）
  │   ├── maps（多张地图）
  │   ├── npcs（NPC 配置）
  │   ├── quests（任务）
  │   └── users（归属用户）
  └── campus B（分校区）
```

## 四、非功能需求

### 4.1 性能
- 游戏运行 60 FPS（桌面端），≥ 30 FPS（移动端）
- 地图分块加载，控制内存占用
- API 响应时间 < 200ms（P95）
- WebSocket 支持 1000+ 并发在线用户（单校园场景）

### 4.2 兼容性
- Chrome、Firefox、Safari、Edge（最新 2 个版本）
- iOS Safari、Android Chrome
- WebGL 不可用时自动降级到 Canvas 2D

### 4.3 安全
- JWT Token 鉴权，支持刷新
- API 限流（Redis 实现）
- 插件沙箱隔离
- XSS / CSRF 防护
- 用户输入校验

### 4.4 部署与运维
- Docker Compose 一键启动（Demo 阶段）
- 无状态服务设计，支持水平扩展
- Prometheus + Grafana 监控
- GitHub Actions 自动构建部署

## 六、MVP 范围定义

### Phase 1 MVP（对标复刻）
一张地图 + 一个可控制角色 + 三栋可进入建筑 + 五个 NPC + 10 个模态窗口全功能 → 纯前端静态部署

### Phase 2 MVP（校园 Demo）
一张校园主地图 + 一个可控制角色 + 三栋可进入建筑 + 五个 NPC + NPC 对话和任务 + 一条校园新闻 + 一个现实系统链接 + 一个后台管理页面 + 用户登录和进度保存 + Docker Compose 部署

**Phase 2 的完成标准**：用户能够完成"进入校园 → 移动 → 进入建筑 → 与 NPC 对话 → 完成任务 → 后台发布内容"的完整闭环。
