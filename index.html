Under the Hood

How does this portfolio work?

Architecture

This portfolio is built on Phaser.js 3 game framework. The application is divided into multiple layers: the game scene, entity classes (Player, NPC, Monster), UI overlay, Web Workers for heavy computations and services for communication.

An interesting aspect is that UI and Phaser live side by side — the HTML layer renders above the canvas element with modals, menus and text as regular DOM, while the game runs in a GPU-accelerated WebGL context below.

Phaser.js

At the heart of this portfolio is Phaser.js 3 — an open-source game framework for HTML5 games. Phaser can render via WebGL and Canvas 2D, handles physics, animations, sprite sheets, tile maps, audio and input from keyboard, mouse and touch.

In this project, Phaser manages the entire game loop — 60 times per second it updates player and NPC positions, evaluates map collisions, renders tile map layers, manages the camera and animates hundreds of sprites.

Chunk System

The game map contains thousands of tiles (16×16 pixels), which would mean enormous memory consumption if loaded all at once. That's why the map is divided into small chunks — square blocks that are dynamically loaded and released based on the player's position.

The Chunk Manager tracks the camera position and calculates which chunks should be visible. When the player moves to a new area, chunks out of range are destroyed and new ones are created.

NPC System

NPC characters have their own viewport culling — when they leave the visible camera area, their sprite is completely destroyed. When they return to the field of view, they're recreated with full state.

Pathfinding runs in a Web Worker using the EasyStar.js library. NPC routes are pre-calculated, so the worker doesn't need to compute paths in real-time and the main thread stays unblocked.

Tiled Editor

The entire game map is designed in Tiled — an open-source editor for creating tile-based maps. The map consists of multiple layers: terrain, buildings, decorations, collision layer and object layers for NPC routes, markers and zones.

After every map edit, a custom build pipeline processes the TMX file — cuts the map into chunks, extracts collision data, cleans unused tiles from tilesets and generates optimized JSON files for runtime.

Optimization

Performance is a priority at every level. Chunk loading ensures only the player's surroundings are in memory. NPC viewport culling destroys and creates sprites based on visibility. Pathfinding runs in a separate Web Worker.

Assets are loaded lazily — textures, sounds and sprite sheets are downloaded only when needed. Images use the modern WebP format with PNG fallback. Fonts have pre-generated fallback metrics to prevent layout shifts.
